# Оптимизация логирования диагностики редакторов

## Проблема
Слишком много логов диагностики редакторов засоряли консоль, что затрудняло отладку.

## Решение
Оптимизирована система логирования диагностики редакторов для вывода информации только в ключевые моменты - при начале и окончании drag-and-drop операций.

## Изменения

### 1. `use-editor-diagnostics.ts`
- Добавлен параметр `logOnlyOnDragEvents` для условного логирования
- Добавлена функция `logDiagnosticsOnDragEvent()` для логирования при драг-событиях
- Диагностика теперь логируется только при `dragStart` и `dragEnd` событиях

### 2. `drag-debug-logger.ts`
- Добавлен callback механизм для интеграции с диагностикой редакторов
- Методы `setEditorDiagnosticsCallback()` и `clearEditorDiagnosticsCallback()`
- Автоматический вызов диагностики при начале и окончании драга

### 3. `page-editor.tsx`
- Включен режим `logOnlyOnDragEvents: true`
- Настроена интеграция между `dragDebugLogger` и `editorDiagnostics`
- Добавлен cleanup для callback'а при размонтировании

## Дополнительные оптимизации

### 4. `page-editor.tsx` - убраны постоянные логи
- Убраны постоянные логи готовности редакторов
- Логи выводятся только при изменении состояния готовности
- Отключена периодическая диагностика (каждые 2 секунды)

### 5. `use-dnd-events.ts` - оптимизированы логи retry
- Логи готовности редакторов выводятся только при проблемах или на последних попытках
- Детальная диагностика блоков только при ошибках
- Логи retry только на последних 3 попытках

## Дополнительные оптимизации логирования

### 6. `dnd-test-logger.ts` - throttling для DND_TEST_FALLBACK_SYSTEM
- Добавлен throttling для SUCCESS логов (1 секунда между одинаковыми логами)
- Ошибки логируются всегда, SUCCESS логи - с ограничением частоты
- Убраны сотни повторяющихся логов при dragover событиях

### 7. `enhanced-block-handle.tsx` - throttling для Element drag detected
- Добавлен throttling для логов "Element drag detected" (2 секунды)
- Убраны повторяющиеся логи при каждом dragover событии

### 8. `block-drop-zone.tsx` - throttling для Drag over event received
- Добавлен throttling для логов "Drag over event received" (1 секунда)
- Убраны повторяющиеся логи при каждом dragover событии

### 9. `block-editor.tsx` - throttling для логов монтирования
- Добавлен throttling для логов MOUNTING/MOUNTED/UNMOUNTING (5 секунд)
- Убраны повторяющиеся логи при перемонтировании блоков

## Результат
- Диагностика редакторов теперь выводится только при начале и окончании drag-and-drop операций
- Убраны все постоянные логи готовности редакторов
- Убраны сотни повторяющихся логов при dragover событиях
- Убраны повторяющиеся логи монтирования блоков
- Консоль стала чище и более информативной
- Сохранена вся функциональность диагностики для отладки проблем с редакторами
- Логи выводятся только при реальных проблемах или изменениях состояния
- Применен throttling для всех избыточных логов

## Использование
Диагностика автоматически срабатывает при:
1. **Начале драга** - показывает состояние всех редакторов перед операцией
2. **Окончании драга** - показывает состояние всех редакторов после операции

Это позволяет видеть, как изменилось состояние редакторов в результате drag-and-drop операции.
